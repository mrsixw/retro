# Retrospective

1. Read the session's primary artifacts, commands, failures, and final result.
2. Find evidence-backed improvement candidates in navigation, automated checks, coding standards, global guidance, tool economy, and information access.
3. Separate preventable defects from unavoidable complexity.
4. Recommend the smallest durable improvement and state what evidence supports it.
5. Present candidates in severity order without editing the environment unless explicitly requested.

Avoid turning one incident into a universal rule without evidence that the failure will recur.
